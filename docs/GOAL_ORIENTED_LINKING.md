# 思考を収束させる線設計メモ

## Summary

このメモは、マインドマップに大きな新モードを足さず、ノード間の線の繋ぎ方・見せ方の工夫で「現状からゴールへ思考を収束させる」価値があるかを整理するためのものです。

まずは既存の親子線、補助線、手動アンカーの延長で考えます。新しい状態管理や専用ワークフローを増やす前に、線だけで思考の流れを十分に表現できるかを検証します。

## Key Ideas

- 「現状」と「ゴール」は特別な状態ではなく、通常ノードとして表現する。
- 発散したノードを、ゴールに近づく理由、障害、前提、次アクションとして線で結ぶ。
- 既存の親子構造は変えない。線は思考の関係性を示すだけにする。
- 価値がありそうなら、補助線に軽い意味を持たせる案を検討する。
  - 例: `supports` / `blocks` / `depends` / `next`
  - v1 ではラベルや複雑なワークフローではなく、線種、色、矢印程度に留める。

## Implementation Candidate

### 最小案

- 既存の補助線を使いやすくする。
- ゴールノードへ向かう補助線だけ、矢印や強調表示ができるか検討する。
- Command Palette から「選択ノード -> ゴール/別ノードへ線を追加」を実行しやすくする。
- 既存の補助線追加フローを壊さず、線の見た目だけで思考の方向を補助する。

### 少し拡張する案

- `customLinks` に任意の `kind` を追加する。
- `kind` ごとに線の見た目を変える。
- `kind` は思考整理に必要な最小限に絞る。
  - `supports`: ゴールや主張を支える
  - `blocks`: ゴールへの障害になる
  - `depends`: 前提や依存関係を示す
  - `next`: 次に進むべき流れを示す
- Undo/Redo、保存、旧データ補完に含める。

### 避ける案

- 専用の収束モードを追加する。
- ノードに採用/保留/棄却などの状態を増やす。
- AI 前提にする。
- 別ビューや大きなワークフローを作る。
- 線の意味を増やしすぎて、操作や見た目を重くする。

## Value Check

作る価値がある条件:

- ゴールに向かう論点の流れが、線を見るだけで分かる。
- 発散したノードのうち、どれがゴールに効くか整理しやすい。
- 既存の軽快なマインドマップ操作を邪魔しない。
- ノード本文や付箋だけでは表しづらい「関係性」や「方向」が表現できる。

作らない条件:

- ただ補助線の種類が増えるだけで、思考整理に効かない。
- 線の意味が増えすぎて操作が重くなる。
- ノード本文や付箋で十分表現できる。
- 親子構造と補助線の役割が混ざり、マップの読み方が分かりにくくなる。

## Test / Validation Notes

この md 作成自体には自動テストは不要です。

内容確認では以下を見る:

- 「収束モード追加ありき」になっていない。
- 既存の線機能の延長として実装できる。
- v1 の最小実装と、作らない条件が明確。
- 次に実装するなら `customLinks` の軽い拡張で始められる。
- 親子構造、補助線、付箋、自動整列の既存仕様を変えない方針になっている。

## Next Step Candidate

次に実装へ進む場合は、まず `customLinks.kind` を追加するより前に、既存の補助線操作だけで「現状ノード -> 論点 -> ゴールノード」の流れを手作業で作ってみるのがよいです。

それで価値が見えた場合だけ、`kind` と線の見た目を最小限追加します。
